## 1. 목적과 범위

한 사용자가 파티 콘셉트의 정적 웹에서 `필수 동의·생년월일 입력 → 오늘의 간이 사주와 입력 정보 확인 → 타로 1장 뽑기 → 사주+카드 결과 확인 → PNG 다운로드`를 완주한다.

`타로섯다`는 서비스명이며 인터넷 도박이나 대전 게임이 아니다. 호스트·게스트, 룸, PIN/QR, 순위·족보·승패·베팅, 재추첨은 범위에 없다.

## 2. 액터와 공통 규칙

| 액터/경계 | 책임 |
|---|---|
| 사용자 | 동의하고 생년월일을 입력·확인한 뒤 카드 한 장을 뽑고 결과를 내려받는다. |
| 브라우저 앱 | 입력 검증, 간이 사주 계산, 22장 중 한 장 선택, 결과 표시와 PNG 생성을 로컬에서 수행한다. |

- 입력은 필수 동의 항목과 생년월일뿐이다. 출생시각을 받지 않으므로 항상 `생년월일 기반 오늘의 간이 사주`라고 표시한다.
- 생년월일은 확인 화면까지 브라우저 메모리에만 유지하고, 카드 뽑기 성공 시 지운다.
- 생년월일과 결과를 API, URL, 로그, 분석 도구, `localStorage`, `sessionStorage`, IndexedDB, 쿠키에 보내거나 저장하지 않는다.
- 메이저 아르카나 22장은 가중치 없이 각각 정확히 `1/22` 확률이다.
- 성공한 뽑기는 페이지 세션당 한 번이다. 새로고침 이후까지 제한한다고 주장하지 않는다.
- 결과는 엔터테인먼트용이며 중요한 의사결정의 근거가 아님을 입력 전과 결과에 표시한다.

## 3. 유스케이스

### UC-01. 동의하고 생년월일을 입력한다

- **주 액터:** 사용자
- **사전조건:** 앱의 히어로 화면이 열려 있다.
- **트리거:** 사용자가 `오늘의 사주 확인하기`를 누른다.
- **기본 흐름:**
  1. 앱이 파티 콘셉트 이미지, 개인정보 처리 안내, 엔터테인먼트 고지를 보여준다.
  2. 사용자가 필수 항목에 동의하고 `<input type="date">`로 생년월일을 입력한다.
  3. 앱이 동의 여부와 날짜 형식·존재·미래 날짜 여부를 검증한다.
  4. 앱이 로컬에서 오늘의 간이 사주를 계산한다.
- **예외 흐름:** 미동의 또는 잘못된 날짜면 첫 오류 필드로 포커스를 옮기고 사주 계산을 시작하지 않는다. 계산 실패 시 임의 결과를 만들지 않고 입력 수정 경로를 제공한다.
- **사후조건:** 유효한 경우 `SAJU_CONFIRM`으로 이동하고, 생년월일은 확인을 위해 브라우저 메모리에만 남는다.
- **수용 기준:** `AC-01`, `AC-02`, `AC-08`.

### UC-02. 입력 정보와 오늘의 간이 사주를 확인한다

- **주 액터:** 사용자
- **사전조건:** UC-01의 검증과 계산이 성공했다.
- **기본 흐름:**
  1. 앱이 입력한 생년월일, 오늘의 대표 오행, 제목, 한 줄 해설과 간이 해석 고지를 보여준다.
  2. 사용자가 잘못 입력했다면 `다시 입력`을 눌러 UC-01로 돌아간다.
  3. 정보가 맞으면 `타로카드로 오늘의 행운 1장 뽑아보기`를 누른다.
- **사후조건:** CTA가 한 번만 추첨을 시작하고 중복 클릭은 추가 추첨을 만들지 않는다.
- **수용 기준:** `AC-03`, `AC-04`.

### UC-03. 오늘의 타로카드 한 장을 뽑는다

- **주 액터:** 사용자, 브라우저 앱
- **사전조건:** 사주 확인이 완료됐고 아직 성공한 추첨 결과가 없다.
- **기본 흐름:**
  1. 앱이 22장 정적 카드 카탈로그의 완전성과 고유성을 확인한다.
  2. Web Crypto와 rejection sampling으로 `0..21` 중 하나를 균등 선택한다.
  3. 선택된 카드 한 장을 현재 세션 결과로 확정하고 추첨 CTA를 잠근다.
  4. 원본 생년월일을 상태와 DOM에서 지운다.
- **예외 흐름:** 카탈로그 오류 또는 Web Crypto 실패 시 `Math.random()`으로 대체하지 않는다. 결과를 만들지 않고 오류를 표시하며, 성공 전에는 같은 CTA로 재시도할 수 있다.
- **사후조건:** `DrawResult`가 정확히 하나이며 각 카드의 이론 확률은 `1/22`다.
- **수용 기준:** `AC-04`, `AC-05`, `AC-08`.

### UC-04. 사주와 카드 결과를 확인한다

- **주 액터:** 사용자
- **사전조건:** UC-03에서 카드 한 장이 확정됐다.
- **기본 흐름:** 카드 이미지, 한·영문 카드명, 카드 해설, 오늘의 간이 사주 요약과 두 결과의 연결 문구를 한 화면에 표시한다.
- **예외 흐름:** 카드 이미지 로드가 실패해도 카드명·해설·사주 텍스트는 유지하고 이미지 오류를 안내한다.
- **사후조건:** 결과에 생년월일, 순위, 족보, 승패, 베팅, 재추첨 UI가 없다.
- **수용 기준:** `AC-06`, `AC-08`.

### UC-05. 사주+타로 결과 PNG를 내려받는다

- **주 액터:** 사용자, 브라우저 앱
- **사전조건:** UC-04의 결과가 표시돼 있다.
- **트리거:** 사용자가 `PNG로 저장`을 누른다.
- **기본 흐름:**
  1. 앱이 동일 출처 카드 이미지와 결과 문구를 Canvas에 그린다.
  2. `canvas.toBlob('image/png')`으로 파일을 만들고 네이티브 다운로드를 시작한다.
  3. `<a download>` 클릭을 발생시킨 다음 작업 큐에서 임시 Object URL을 해제한다.
- **예외 흐름:** 이미지·Canvas·Blob 생성이 실패하면 결과 화면은 유지하고 다운로드 오류와 재시도 버튼만 보여준다.
- **사후조건:** 내려받은 이미지에는 카드 이미지·카드명·해설·사주 요약·엔터테인먼트 고지가 있고 생년월일은 없다.
- **수용 기준:** `AC-07`, `AC-08`.

## 4. 수용 기준

| ID | 검증 기준 |
|---|---|
| `AC-01` | 필수 동의 전에는 날짜 제출과 사주 계산이 진행되지 않는다. |
| `AC-02` | 빈 값·존재하지 않는 날짜·미래 날짜를 거부하고 오류가 입력과 연결된다. |
| `AC-03` | 확인 화면에 입력한 생년월일과 `생년월일 기반 오늘의 간이 사주`가 표시되며 다시 입력할 수 있다. |
| `AC-04` | 정확한 CTA `타로카드로 오늘의 행운 1장 뽑아보기`가 성공한 추첨을 한 번만 만든다. |
| `AC-05` | 카탈로그가 정확히 22장이고 모든 카드의 이론 확률이 `1/22`이며 두 번째 결과가 없다. |
| `AC-06` | 결과 화면에 카드 이미지·이름·해설과 사주 요약·연결 문구가 함께 표시된다. |
| `AC-07` | PNG 다운로드가 성공하고 생년월일은 이미지에 없으며, 실패해도 HTML 결과는 유지된다. |
| `AC-08` | Network·URL·콘솔·브라우저 Storage에 생년월일과 결과 데이터가 남지 않는다. |

## 5. 후속 검토 사항

- 간이 사주 규칙과 카드 문구는 엔터테인먼트 하우스 룰로 리뷰 승인한다.
- 생성된 22장 이미지의 이용 권리와 카드별 표현을 최종 검수한다.
- ADR-0001의 `1080×1350` PNG가 실기기에서 읽기 쉬운지 계속 검증한다.
- 브라우저 증거는 `docs/QA_EVIDENCE.md`에 기록한다.
