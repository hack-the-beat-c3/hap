# 구현 계획 — 사주·궁합 파티 서비스 (3 기능)

> 제품 한 줄: 생년월일 기반 사주·오행 케미와 **1인 1장 타로 단판**으로, 파티 현장에서 다 같이 오늘의 운세 순위와 궁합을 겨루는 멀티플레이 서비스.
> 스택: 기존 그대로 — React 19 + Vite + TS (`package.json` 확인). 새 프레임워크/상태관리 추가 없음 (AGENTS.md §6).
> 게이트 목표: "파티 현장 단판"이 핵심 전제 → 주제 적합성 ×1.00 구간.

이 계획은 `docs/RUBRIC.md`의 **상한 해제 조건**을 기능 설계에 직접 박아 넣는다. 상한은 "제출물에서 인용 가능한 증거"가 없으면 B/C 항목이 5~6점을 못 넘는 구조라서, 기능 3개를 **각각 특정 상한 규칙을 여는 장치**로 정렬한다.

---

## 기능 1 — 파티룸 생성 & QR/PIN 동반 입장 (호스트 플로우)

**무엇을**: 호스트가 닉네임·생년월일(음/양력, 출생시각 `모름` 허용)을 입력하고 룸을 만들면 PIN·QR이 나온다. 게스트가 QR/PIN으로 들어와 정보를 입력하면 호스트 화면에 준비 상태가 실시간으로 뜬다.

**왜 이 기능인가 (루브릭 매핑)**:
- **A1 (핵심 플로우 완주, 40%)**: 3단계 중 1·2단계. 배포 URL에서 완주 증거(QA_EVIDENCE)가 A1·A3 만점의 전제.
- **B3 (파티형 확산, 상한 6 → 해제)**: 초대·동반 참여 **없이는 제품이 성립하지 않음**. 혼자 결과만 보는 경로는 비범위. QR 초대 → 2인 이상 세션 동시 접속이 브라우저 evidence로 확인되면 B3 상한(6)을 넘는다.
- **A4 (완성도)**: 잘못된 PIN, 만원 룸(정원 2~15), 중복 입장, 재연결 처리 포함.

**최소 구현**:
- 실시간: 새 의존성 전에 사다리 확인 — 우선 브라우저 네이티브(`BroadcastChannel` 로컬 데모) → 다기기 필요 시 이미 검토된 경량 실시간(ADR로 채택). 서버 권위 상태는 `room phase / participants / deck·deal / result`로 제한 (AGENTS.md §6).
- 원본 생년월일은 **브라우저에서만** 계산, 서버엔 닉네임·파생 오행·룸 상태만 전송 (개인정보 하드룰).
- 체크: 정원 초과·중복 닉네임·PIN 미스매치 가드에 최소 실행 테스트 1개.

## 기능 2 — 1인 1장 공정 셔플 + 동시 공개 리캡 (승부 판정)

**무엇을**: 전원 준비되면 호스트가 일괄 공개. 룸 공유 덱(메이저 아르카나 22장)을 **Web Crypto 기반 Fisher–Yates**로 한 번 섞어 참가자에게 중복 없이 한 장씩 배분. 최고 순위 1명을 `오늘 파티의 최강 운세`로 발표하고, 모든 화면에 같은 우승자·결과가 뜬다.

**왜 이 기능인가**:
- **A1 (40%)**: 3단계 중 3단계(동시 공개·리캡). 여기까지 완주해야 A1 만점.
- **A2 (배포·안정성)**: 모든 화면이 **같은 결과**를 봐야 함 → 서버 권위 판정으로 데스크톱·모바일 동기화.
- **공정성 (차별점 근거, C3)**: 생년월일에 따른 카드 유불리 없음(룸 단위 공정 셔플). "사주로 이기고 지는 게 아니라 재미로 겨룬다"는 안전 포지션이 사행성 리스크를 피하고 C3 논증에 쓰임.
- **A4**: 카드 순위는 전통 서열이 아닌 **파티 하우스 룰**임을 명시. 불쾌감·낙인 없는 문구.

**최소 구현**:
- 셔플: Web Crypto Fisher–Yates. **중복·누락 테스트**가 이 기능의 필수 체크(비자명 로직).
- 사주·오행은 **개인화 문구/케미에만** 사용, 승부 카드엔 영향 없음.
- 결과는 엔터테인먼트용 고지. 현금·베팅·유료 재추첨 금지.

## 기능 3 — 오행 궁합 케미 매트릭스 + 공유용 리캡 카드 (확산·리텐션)

**무엇을**: 공개 후, 참가자 간 **오행 상생·상극 궁합**을 케미 매트릭스로 보여준다("오늘 가장 케미 좋은 짝", "상극 주의 조합"). 룸 전체 요약을 **공유용 결과 카드(이미지)**로 만들어 카카오톡/인스타로 내보낸다.

**왜 이 기능인가**:
- **궁합 = 사용자 요구 핵심**. 개인 카드 순위(경쟁) 위에 **관계(궁합)** 레이어를 얹어 "다 같이 보는 재미"를 만든다.
- **B3 (확산, 상한 6)**: 결과 카드 공유가 **다음 파티의 초대 훅**이 되도록 — 카드에 "우리 파티 다시 하기" 룸 생성 딥링크 포함. 단, 공유 버튼만으로는 상한 못 넘음(루브릭 명시). B3 상한은 **기능 1의 동반 입장 동작**으로 여는 게 정석이고, 이 기능은 그걸 보강.
- **B4 (리텐션, 상한 5)**: 재방문 트리거를 **제품 동작으로** 구현 — "지난 파티 최강 운세" 리캡 + "다음 모임 룸 만들기" CTA. 트리거 시점(파티 종료 직후 공유 카드)이 특정됨 → 상한 해제 조건 충족.
- **C3 (차별점)**: 카카오톡 단톡방·인스타·Kahoot이 **못 하는 것** = 사주·오행 기반 실시간 궁합 + 현장 단판 판정. 구체 대체재 지목 논증에 사용.

**최소 구현**:
- 오행 상생/상극은 고정 규칙표(목화토금수) — 라이브러리 불필요, 한 줄 룩업 테이블.
- 공유 카드: `<canvas>` 또는 SVG→이미지 (브라우저 네이티브, 새 의존성 없음).
- 체크: 상생/상극 매핑 정확성 테스트(예: 목→화 상생, 목→토 상극).

## 3단계 검증 플로우 (배포 URL에서 증거 확보 — A1/A3 전제)

1. **생성**: 호스트가 생년월일 입력 → 룸 생성 → PIN·QR 획득. (기능 1)
2. **참여·배분**: 게스트가 QR/PIN 입장 → 정보 입력 → 준비 상태 실시간 반영 → 숨겨진 카드 1장 수령. (기능 1+2)
3. **공개·리캡**: 호스트 공개 → 전 화면 동일 우승자 + 오행 궁합 매트릭스 + 공유 카드. (기능 2+3)

호스트+게스트 2개 이상 세션, 모바일 390×844 / 데스크톱 1440×900, 콘솔 에러 0으로 캡처해 `docs/QA_EVIDENCE.md`에 URL·시각·commit SHA와 함께 기록.

## 루브릭 커버리지 요약

| 기능 | 직접 여는 항목 | 상한 해제 |
|---|---|---|
| 1. 룸 생성·QR 동반 입장 | A1, A2, B3, A4 | **B3(6)** — 동반 참여 라이브 동작 |
| 2. 공정 셔플·동시 공개 | A1, A2, A4, C3 | 공정성 = C3 논증 근거 |
| 3. 오행 궁합·공유 리캡 | B3, B4, C3 | **B4(5)** — 재방문 트리거 제품 구현 |

> 기능으로 못 여는 상한(문서 증거 필요)은 별도 산출물로 채운다: **B1**(5인 인터뷰 인용 5개), **B2**(모수·주체·시점 2개 이상 고유명사/숫자), **C1**(지불자·시점·금액 3개), **C2**(상향식 대상×빈도×단가), **C4**(건당 원가 숫자). 이는 `docs/RESEARCH.md`·`docs/PITCH_SCRIPT.md`에서 담당.
