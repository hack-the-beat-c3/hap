# PRD — 1:1 현장 QR 사주 궁합 매칭 (1-on-1 Elemental Synergy Match)

- **Owner**: 팀 DRI
- **Reviewer**: 팀 Reviewer
- **Status**: Ready for Implementation (자율 승인)
- **Related ADR**: ADR-0003 (예정)
- **Related Documents**: `AGENTS.md` §2.2, §2.4, `docs/design/01_USE_CASE_SPEC.md`

---

## 1. 배경 및 목적

### 1.1 배경
- 앞서 구현된 '부족한 오행 찾기 미션'을 통해 참가자들은 파티 룸에서 대화를 나눌 상대방 1~3명을 지목받았습니다.
- 실제로 파티 현장에서 두 사람이 마주쳤을 때, **스마트폰의 개인 QR 코드를 서로 스캔하거나 사주 프로필을 원클릭으로 교환**하여 즉석에서 두 사람만의 **1:1 상세 궁합 분석과 아이스브레이킹 대화 카드**를 열어볼 수 있는 결정적 계기가 필요합니다.

### 1.2 목적
1. **자연스러운 1:1 인터랙션 유발**: "제 QR 한번 찍어보실래요?"라는 직관적인 행동 유도.
2. **사주·오행 기반 1:1 시너지 점수 & 케미 리포트 제공**: 두 사람의 오행 상생 관계, 시너지 점수(70~99점의 긍정적 칭찬형 스코어), 대화 주제 2~3가지를 제공.
3. **인연 수집(소셜 컬렉션)의 재미**: 파티 동안 1:1 매칭에 성공한 인연들을 내 목록에 배지 형태로 기록.

## 2. 제품 계약 및 하드룰 준수

| 항목 | 원칙 및 규칙 |
|---|---|
| **개인정보 보호** | QR 코드 페이로드에는 `닉네임, 주 오행, 오행 분포 수치, 생성 타임스탬프`만 포함되며, **원본 생년월일·시각은 일체 포함하지 않음** |
| **서버 비의존성** | 클라이언트 간 QR 직접 스캔 또는 URL 딥링크/코드 교환으로 P2P 즉시 계산 (서버 트래픽 0) |
| **불쾌감 방지** | 상극이나 부정적 점수(낙제점, 파국 등)는 절대 배제하고, 모든 조합을 **"서로 다른 매력으로 채워주는 관계"** 등 긍정적 시너지로 표현 |
| **공정성 분리** | 타로 섯다 게임 승부나 카드 서열에는 영향 없음 |
| **Ponytail 원칙** | 복잡한 외부 의존성 없이 표준 Canvas 기반 QR 생성 및 웹 네이티브 API / 코드 교환 fallback 탑재 |

## 3. 사용자 흐름 (User Flow)

```
[내 미션 카드 확인]
       │
       ▼
[1:1 케미 매칭 버튼 클릭] ───► [내 QR 코드 모달 노출 (닉네임 + 오행 기운)]
                                      │
                                      ▼ 상대방이 스마트폰 카메라로 스캔
                               [상대방 사주 페이로드 디코딩]
                                      │
                                      ▼
                      [1:1 오행 시너지 궁합 리포트 팝업]
                      - 케미 스코어 (예: 96점 "완벽한 보완 콤비")
                      - 두 사람의 오행 순환 다이어그램
                      - 오늘의 추천 대화 질문 2가지
                      - "인연 목록에 저장" 클릭 시 로컬 컬렉션 추가
```

## 4. 핵심 사양 및 알고리즘

### 4.1 QR 데이터 페이로드 규격 (Safe Payload)
```typescript
export interface SharedSajuPayload {
  version: 1;
  id: string; // 익명 세션 ID
  nickname: string;
  primaryElement: FiveElement;
  elements: ElementCounts; // { 木, 火, 土, 金, 水 }
  timestamp: number;
}
```
- URL 안전한 Base64 인코딩 스트링으로 직렬화 (예: `hap://match?p=eyJ2ZXJzaW9u...`)

### 4.2 1:1 케미 점수 및 유형 산출 (`calculateSynergyMatch`)
- **점수 체계 (75점 ~ 99점)**:
  - 부족 오행을 서로 채워주는 경우 (상호 보완): **95 ~ 99점** ("하늘이 맺어준 상호 보완 콤비")
  - 상생 관계 (생해주거나 생을 받는 관계): **88 ~ 94점** ("서로의 에너지를 폭발시키는 든든한 조력자")
  - 동일 오행 (닮음): **85 ~ 90점** ("말하지 않아도 통하는 영혼의 단짝")
  - 오행 조화형 (그 외 조합): **78 ~ 84점** ("새로운 시야와 영감을 선물하는 흥미진진한 케미")
- **추천 대화 주제 생성**:
  - 두 사람의 오행 특성에 맞춘 질문 2가지 (예: 火와 水 조합 -> "열정적으로 몰입하는 취미 vs 차분하게 힐링하는 휴식 방법")

### 4.3 인연 컬렉션 (Party Connections)
- 파티 현장에서 1:1 매칭을 완료한 참가자를 로컬 상태(또는 룸 메모리)에 저장.
- 완성된 인연 수와 채운 오행 기운 목록을 한눈에 볼 수 있는 '오늘 만난 인연' 서브 탭 제공.

## 5. UI/UX 화면 구성

1. **`MatchModal` / `MatchHub`**:
   - 탭 1: **내 QR 코드 보여주기** (고화질 QR + 내 오행 뱃지 + "상대방에게 보여주세요")
   - 탭 2: **QR 스캔 / 코드 입력하기** (카메라 스캐너 또는 1클릭 파티원 선택/코드 붙여넣기 fallback)
2. **`MatchResultCard` (1:1 궁합 결과 뷰)**:
   - 두 사람의 닉네임과 오행 뱃지 대결 구도
   - 케미 스코어 게이지 (애니메이션 지원)
   - 핵심 시너지 타이틀 및 2줄 해설
   - 추천 대화 아이스브레이킹 카드
   - "인연 목록에 추가" 및 "결과 공유하기" 버튼
3. **`ConnectionHistory` (오늘 맺은 인연 목록)**:
   - 내가 스캔하여 궁합을 맞춘 참가자 카드 리스트

## 6. 예외 처리 (Edge Cases)

| 예외 상황 | 대응 방안 |
|---|---|
| 카메라 권한 거부 또는 미지원 브라우저 | 룸 참가자 드롭다운 선택 또는 텍스트 코드 직접 복사/붙여넣기 fallback 제공 |
| 자기 자신의 QR 스캔 | "나 자신과의 궁합은 100점! 하지만 다른 파티원의 QR을 스캔해주세요 😊" 안내 토스트 |
| 잘못되거나 깨진 QR 데이터 | "유효하지 않은 HAP 사주 코드입니다." 에러 얼럿 및 재시도 안내 |
| 이미 매칭 완료된 참가자 재스캔 | 이전 매칭 결과를 최신으로 갱신하여 렌더링 (중복 에러 방지) |

## 7. 구현 단계 (Execution Plan)

1. **도메인 모델 & 계산 로직 (`src/lib/match/`)**:
   - `calculateSynergyMatch(me, opponent)` 순수 함수 + 단위 테스트
   - `encodeSajuPayload(profile)`, `decodeSajuPayload(code)` 직렬화 함수 + 단위 테스트
2. **QR 생성 및 스캐너 유틸리티**:
   - 브라우저 네이티브 Canvas 기반 경량 QR 렌더러
   - 카메라 스캐너 & 코드 복사 fallback
3. **UI 컴포넌트 (`src/components/match/`)**:
   - `MyQrCodeView.tsx`: 내 QR 코드 표시 뷰
   - `QrScannerView.tsx`: 카메라 스캔 / 코드 입력 뷰
   - `MatchResultCard.tsx`: 1:1 궁합 결과 및 아이스브레이킹 대화 카드
   - `MatchHubModal.tsx`: QR 교환 및 결과 모달 통합
   - `ConnectionHistoryList.tsx`: 파티에서 만난 인연 히스토리
4. **통합 및 검증**:
   - `PartyChemistryPlayground` 및 메인 화면에 1:1 매칭 버튼 연동
   - Vitest 단위 테스트 100% 통과, 린트/빌드 검증, ADR-0003 작성 및 커밋/푸시
