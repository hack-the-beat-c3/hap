# ADR-0001: 타로섯다 1인용 MVP 아키텍처

- Status: Proposed
- Date: 2026-08-29
- Owners: 김형준 (`@procloudkim`), Reviewer 미정
- Related: `AGENTS.md §2`, `docs/process/procloudkim/PROCESS.md`, `docs/design/01_USE_CASE_SPEC.md`~`05_ERD.md`

## Context

현재 저장소에는 React 19와 Vite 8 기본 화면만 있으며 타로 기능은 구현되지 않았다. 타로섯다는 도박·대전 게임이 아니라 사용자가 생년월일 기반 오늘의 간이 사주를 확인하고, 메이저 아르카나 22장 중 행운 카드 한 장을 뽑아, 사주와 카드 해설이 합쳐진 결과 이미지를 내려받는 1인용 파티 콘텐츠다.

생년월일은 결과 생성에만 필요하며 저장할 이유가 없다. 오늘 배포할 MVP에는 회원, 파티룸, 실시간 통신, 순위, 결제가 필요하지 않다.

## Decision

1. 기존 React·TypeScript·Vite 구성을 유지하고 백엔드를 만들지 않는다.
2. 사용자는 필수 동의 후 생년월일을 입력한다. 입력값은 브라우저 메모리에서만 사용하며 네트워크·로그·저장소로 보내지 않는다.
3. 출생시각을 받지 않으므로 결과는 `생년월일 기반 오늘의 간이 사주`라고 표시한다.
4. 사주 확인 후에만 `타로카드로 오늘의 행운 1장 뽑아보기` CTA를 활성화한다.
5. 카드 카탈로그는 메이저 아르카나 22개의 정적 데이터와 동일 출처의 WebP 이미지로 제공한다.
6. 카드는 Web Crypto로 균등하게 한 장만 선택한다. 각 카드 확률은 `1/22`이며 재추첨, 족보, 순위, 승패가 없다.
7. 결과 화면은 사주 요약, 카드 이미지, 카드명, 해설을 함께 보여준다.
8. 다운로드 이미지는 브라우저 Canvas API로 구성하고 `canvas.toBlob()`과 임시 링크로 PNG를 저장한다.
9. MVP PNG 규격은 모바일 공유에 맞춘 `1080×1350`으로 고정한다.

## Alternatives

- **호스트·게스트 파티룸:** 이번 도메인의 사용자 흐름과 무관하고 백엔드·실시간 복잡도만 추가하므로 제외한다.
- **카드 족보·가중 확률:** 도박 또는 대전 게임으로 오해될 수 있고 오늘의 행운 한 장이라는 목적과 맞지 않아 제외한다.
- **생년월일 서버 저장:** 재방문 복원에는 편리하지만 MVP에 불필요한 개인정보 보유가 생겨 제외한다.
- **DOM 캡처 라이브러리:** 결과 다운로드는 편하지만 새 의존성이 필요해 Canvas API로 대체한다.

## Consequences

- 장점: 정적 웹으로 즉시 배포할 수 있고 개인정보와 운영 비용을 최소화한다.
- 장점: 입력 → 사주 확인 → 카드 한 장 → 다운로드라는 데모 흐름이 짧고 명확하다.
- 제한: 새로고침하면 입력과 결과가 사라진다.
- 제한: 출생시각이 없으므로 완전한 사주팔자라고 표현할 수 없다.
- 제한: Canvas에 사용하는 이미지는 동일 출처 자산이어야 안정적으로 PNG를 생성할 수 있다.

## Verification / Rollback

- 동의하지 않으면 생년월일 입력과 다음 단계 진행이 불가능한지 확인한다.
- 유효하지 않은 생년월일을 거부하고 정상 입력에서는 사주 확인 화면이 표시되는지 확인한다.
- 22장 이외의 카드 ID가 나오지 않고 한 흐름에서 정확히 한 번만 뽑히는지 테스트한다.
- 네트워크, `localStorage`, `sessionStorage`, 콘솔에 생년월일이 남지 않는지 검사한다.
- 생성한 PNG에 사주 요약, 카드 이미지, 카드명, 해설이 모두 포함되는지 확인한다.
- Canvas 구현이 데모 시간 내 실패하면 다운로드만 비활성화하고 화면 결과를 유지하되, 다운로드 완료를 주장하지 않는다.
