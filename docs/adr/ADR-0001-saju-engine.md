# ADR-0001: 팀원 3 사주·오행 엔진
- Status: Accepted
- Date: 2026-08-29
- Owners: DRI 배정 대기(AGENTS.md §1, 팀 R&R 미정), Reviewer 이무원(lmwmason) — 2026-08-29 채팅 내 승인, PR #1 정식 리뷰는 별도 진행
- Related: PRM.md Goal 1, AGENTS.md §2.2/§3/§6

## Context

생년월일 기반 개인화 문구와 참가자 케미를 만들려면 양력·음력 변환, 윤달 검증, 간지 계산 및 오행 파생의 경계를 먼저 정해야 한다. 원본 생년월일과 출생시각은 민감한 입력이므로 브라우저 밖으로 나가지 않는 구조가 필요하다. 현재 `package.json`과 `pnpm-lock.yaml`에는 `lunar`, `calendar`, `dayjs`, `date-fns`, `moment`, `solarlunar`에 해당하는 기존 의존성이 없고, 테스트 프레임워크 및 `test` 스크립트도 없다(저장소 직접 확인, 2026-08-29).

우선 검토 후보인 `korean-lunar-calendar` 0.4.0은 MIT 라이선스이며 2026-06-15에 배포되었다. 런타임 의존성 없이 변환표를 번들해 네트워크 호출 없이 동작하고, 양력과 한국 음력을 양방향 변환한다. KARI/KASI 음양력 표준을 따르며 음력 1000-01-01~2050-11-18, 양력 1000-02-13~2050-12-31을 지원한다. 연·월·일의 한국어·한자 간지 문자열, TypeScript 및 ESM/CJS/브라우저 빌드를 제공하고, 윤달을 명시적으로 다루며 불가능한 윤달 날짜를 검증에서 거부한다. 다만 시간대, 일광 절약 시간제 및 날짜 경계 처리 방식은 명시적으로 문서화되어 있지 않아 별도 위험으로 남긴다. 출처: [korean-lunar-calendar - npm](https://www.npmjs.com/package/korean-lunar-calendar), npm 및 [usingsky/korean_lunar_calendar_js](https://github.com/usingsky/korean_lunar_calendar_js), GitHub (확인일 2026-08-29).

KASI의 공식 직접 기준 사례는 양력 2026년 08월 01일(토)이 음력 2026년 06월 19일이며, 간지는 병오(丙午)년 을미(乙未)월 정미(丁未)일이라는 것이다. 해당 페이지의 조회 범위는 -59년 02월~2050년 12월이고 대한민국 천문법에 따른 공식 양력을 사용한다. 출처: [월별 음양력](https://astro.kasi.re.kr/life/pageView/5), 한국천문연구원 (확인일 2026-08-29).

## Decision

1. **기존 의존성 재사용 가능성:** 관련 달력 또는 날짜 의존성이 현재 없으므로 재사용할 패키지는 없다. 표준 브라우저 기능만으로 한국 음력 변환표를 새로 구현하지 않고, 사람의 승인과 Phase 2 검증을 전제로 최소 후보 하나를 채택한다.

2. **양력·음력·윤달 범위와 권고 후보:** `korean-lunar-calendar` 0.4.0을 우선 권고한다. 오프라인 브라우저 실행, 런타임 의존성 0개, 양방향 변환, 윤달 검증, 간지 출력, 브라우저/TypeScript 빌드 및 명시된 지원 범위가 필요한 경계에 맞기 때문이다. 지원 범위와 속성의 근거는 [korean-lunar-calendar - npm](https://www.npmjs.com/package/korean-lunar-calendar), npm 및 [usingsky/korean_lunar_calendar_js](https://github.com/usingsky/korean_lunar_calendar_js), GitHub (확인일 2026-08-29)이다. 입력은 양력 또는 음력을 구분하고, 음력에는 윤달 여부를 별도 값으로 받는다. 라이브러리가 거부하는 윤달 조합과 지원 범위 밖 날짜는 계산하지 않는다. 실제 의존성 추가는 이 ADR 승인 이후 Phase 2의 별도 변경으로 제한한다.

3. **KST 날짜 경계:** 모든 생년월일과 오늘 날짜 판정은 한국 표준시 KST(UTC+9)의 달력 날짜를 기준으로 한다. JavaScript 런타임의 로컬 시간대나 UTC 변환에 맡겨 날짜가 바뀌지 않도록 `YYYY-MM-DD` 형태의 날짜 값과 명시적 KST 기준을 경계 입력으로 사용한다. 후보 라이브러리의 시간대·날짜 경계 동작은 문서화되지 않았으므로 Phase 2에서 자정 전후 사례를 직접 검증하기 전에는 내부 동작을 가정하지 않는다. 출생시각에 따른 자시 경계와 일주 변경 규칙은 제공된 근거로 확정할 수 없어 사람 승인 전 공개 질문으로 남긴다.

4. **출생시각 `모름`:** 시간주를 생성하지 않으며 결과에 `시간주를 제외한 간이 해석`임을 명시하는 플래그와 사용자 문구를 둔다. 임의 시각이나 정오로 대체하지 않는다.

5. **오늘 날짜 주입:** 계산 진입점은 KST 기준의 `오늘` 날짜를 순수 함수 인자로 받는다. 계산 함수 내부에서 `new Date()`를 직접 호출하지 않아 미래 날짜 판정과 테스트 결과를 결정적으로 만든다.

6. **브라우저 전용 계산과 신뢰 경계:** 원본 생년월일, 양력/음력·윤달 선택 및 출생시각은 브라우저 메모리에서만 검증·계산한다. 이 원본 값은 서버 요청, 실시간 이벤트, 로그, 오류 추적, 분석 도구, 영속 저장소 또는 다른 참가자 화면으로 전송·저장하지 않는다. 서버에는 닉네임, 승인된 파생 오행, 룸/카드 상태만 전달하고 파티 종료 시 파생 데이터도 삭제한다.

7. **지원 불가·잘못된 입력 메시지:** 존재하지 않는 날짜, 불가능한 윤달 조합, 미래 날짜 및 후보 라이브러리 지원 범위 밖 연도는 자동 보정하지 않는다. 어떤 입력 범주가 잘못되었는지 한국어로 명시하고 수정 방법을 안내하며, 계산·전송은 중단한다. 원본 입력값을 오류 로그에 포함하지 않는다.

8. **테스트 도구 제안:** 현재 테스트 프레임워크와 `test` 스크립트가 없다. Phase 2에서 `vitest`를 신규 개발 의존성으로 도입하고 가장 작은 실행 가능한 단위 테스트를 추가할 것을 제안한다. 이 ADR에서는 설치, `package.json` 변경 및 테스트 코드 생성을 하지 않으며, 의존성 추가는 ADR의 사람 승인 후 별도 변경과 리뷰를 거친다.

9. **롤백:** Phase 2 검증에서 기준 사례 불일치, 브라우저 호환 문제 또는 개인정보 경계 위반이 발견되면 `korean-lunar-calendar` 채택을 철회한다. 별도 구현 변경에서 패키지와 잠금 파일 항목, 연결 코드 및 관련 테스트를 함께 제거하고 사주·오행 계산 진입점을 비활성화한다. 검증되지 않은 자체 변환으로 대체하지 않으며 입력 UI에는 계산 기능을 사용할 수 없다는 명시적 상태를 표시한다. 원본 입력이 서버에 추가된 적이 없는지는 네트워크·로그·저장소 검사로 재확인한다.

간지에서 목·화·토·금·수 및 케미 문구를 파생하는 정확한 매핑, 음양 가중치, 월주·일주·시간주 계산 책임을 후보 라이브러리와 애플리케이션 중 어디에 둘지는 제공된 사실만으로 결정할 수 없다. Phase 2 구현 전에 KASI 직접 근거와 사람 리뷰로 규칙을 확정하며, 그 전에는 오행 결과를 임의 생성하지 않는다. 운세 문구는 엔터테인먼트용으로만 작성하고 단정적 예측, 우열 낙인 또는 중요한 의사결정을 유도하는 표현을 쓰지 않는다. 사주·오행 결과는 개인화와 케미에만 사용하며 카드 셔플, 배분, 순위 및 승부 공정성에 영향을 주지 않는다.

## Alternatives

- **직접 변환표·계산식 구현:** 외부 의존성을 피할 수 있지만, 제공된 근거만으로 음양력·윤달·날짜 경계의 정확성을 보장할 수 없어 기각한다.
- **`manseryeok-js`:** 순수 JavaScript, 1000~2050 범위, KASI 기반, DB 불필요를 주장하는 후보이나 심층 검증하지 않았다. 생산 적합성을 주장하지 않는 `ASSUMPTION` 수준 대안이다. 출처: [urstory/manseryeok-js](https://github.com/urstory/manseryeok-js), GitHub (확인일 2026-08-29).
- **`kor-lunar-js`:** KASI 기반 학습 목적이며 `isLeapMonth` 옵션을 제공한다고 소개된 후보이나 심층 검증하지 않았다. 생산 적합성을 주장하지 않는 `ASSUMPTION` 수준 대안이다. 출처: [kahyou22/kor-lunar-js](https://github.com/kahyou22/kor-lunar-js), GitHub (확인일 2026-08-29).
- **서버 계산:** 클라이언트 구현을 줄일 수 있으나 원본 생년월일·시각의 비전송 원칙을 위반하므로 기각한다.

## Consequences

- 음양력 변환과 원본 입력 검증은 브라우저에 격리되고, 서버·로그·분석 도구·다른 참가자는 원본 생년월일과 출생시각을 받거나 저장하지 않는다.
- 출생시각이 `모름`이면 시간주 없는 간이 해석만 제공하며, 계산 정밀도를 과장하지 않는다.
- KST 날짜 경계와 주입된 오늘 날짜로 실행 환경 및 테스트 시각에 따른 비결정성을 줄인다. 자시 경계 규칙은 승인 전까지 구현하지 않는다.
- 운세는 엔터테인먼트 카피로 제한하고 단정적 예측과 낙인을 금지한다. 파생 사주·오행은 카드 셔플과 승부 결과에 관여하지 않는다.
- 새 런타임 및 개발 의존성이 각각 제안되므로, 사람 승인 뒤 별도 변경에서 설치·잠금 파일 검토·라이선스 확인·브라우저 검증이 필요하다.
- 후보의 변환 범위와 KASI 공식 페이지 조회 범위가 동일하다고 가정하지 않는다. 지원 여부는 각 입력에 대해 후보 라이브러리의 명시 범위로 검증한다.
- 오행 파생 규칙과 출생시각의 날짜 경계가 아직 열려 있어 이 ADR 승인만으로 제품 구현을 시작할 수 없다. Phase 2 전에 규칙 근거와 기대 사례를 사람 리뷰로 확정해야 한다.
