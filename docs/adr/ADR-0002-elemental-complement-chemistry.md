# ADR-0002: 오행 보완 케미 및 부족한 오행 찾기 미션 (Elemental Complement Chemistry)

- **Status**: Accepted
- **Date**: 2026-08-29
- **Owners**: 나 (DRI), 팀 전체 (Reviewer)
- **Related**: `PRD_ELEMENTAL_CHEMISTRY.md`, `AGENTS.md` §2.1, §2.2, §2.3, §6, §7

---

## 1. Context (배경)

1. 사주 팔자 기반 파티 네트워킹 앱 '합(HAP)'에서 타로 카드 1장 공개로 우승자가 가려진 후, 참가자들 간의 대화와 상호작용이 단절되지 않도록 명확한 아이스브레이킹 명분이 필요함.
2. 각 참가자가 자신의 사주 오행 분포에서 가장 부족한 기운(부족 오행)을 파악하고, 같은 파티 룸 안에서 해당 기운을 가진 인연을 찾아 말을 걸 수 있는 미션을 제공하고자 함.
3. **절대 제약 (AGENTS.md)**:
   - 생년월일/출생시각 원본 PII는 서버에 전송하거나 저장하지 않고 브라우저 클라이언트에서만 계산.
   - 사주/오행은 개인화 문구와 케미 미션에만 사용하며, 타로 카드 셔플 및 승부 순위에는 일체 영향을 주지 않음 (공정성 보장).
   - Ponytail 개발 원칙: 불필요한 무거운 의존성 없이 순수 함수와 표준 컴포넌트로 구현.

---

## 2. Decision (결정 사항)

1. **부족 오행 산출 규칙 (`pickDeficientElement`)**:
   - 5행 분포 `{ 木, 火, 土, 金, 水 }` 중 최솟값을 가진 오행 1개를 결정론적으로 선택.
   - 동률 최솟값 발생 시 `木 → 火 → 土 → 金 → 水` 순서에 따라 앞선 오행을 선택.
   - 5개 오행 수치가 모두 동일한 경우 `土`를 기본 선택하고 `균형형(isBalanced: true)` 플래그 부여.

2. **관계 분류 및 미션 4종 (`classifyRelation`)**:
   - 상생 순환선(`木 → 火 → 土 → 金 → 水 → 木`)을 기반으로 4종 관계 분류:
     - `채움 (complement)`: 상대의 주 오행이 나의 부족 오행과 일치 (핵심 미션)
     - `밀어줌 (generate)`: 나의 주 오행이 상대의 주 오행을 생함
     - `받음 (support)`: 상대의 주 오행이 나의 주 오행을 생함
     - `닮음 (mirror)`: 나와 상대의 주 오행이 동일
   - 불쾌감이나 낙인을 방지하기 위해 상극 등 부정적 판정은 노출하지 않고 긍정적 시너지 문구로 전환.

3. **지목 인원 및 예외 처리 (`generatePartyMission`)**:
   - 채움 대상자를 우선 선별하며 최대 **3명**까지 지목 (3명 초과 시 입장 순서 `joinedOrder` 기준 선착순 결정론적 선택).
   - 룸 내에 내 부족 오행 보유자가 0명인 경우, `밀어줌` / `받음` / `닮음` 순으로 fallback하여 빈 화면이 발생하지 않도록 보장.
   - 2인 룸부터 15인 만원 룸까지 동일한 알고리즘으로 안전하게 동작.

4. **개인정보 보호 및 화면 계약**:
   - 결과 리캡 카드(`ElementalChemistryCard`): 룸 내부 화면이므로 지목된 참가자 닉네임과 관계 표시.
   - 소셜 공유용 카드(`ShareableResultCard`): 룸 밖으로 나가는 외부 산출물이므로 타인의 닉네임은 철저히 제외하고 본인의 부족 오행과 미션 문구만 포함.

---

## 3. Alternatives Considered (대안 검토)

1. **상극(相剋) 관계를 대립 미션으로 노출하는 방안**:
   - 기각: 파티 현장 네트워킹 분위기에서 부정적인 낙인이나 어색함을 유발할 수 있으므로 긍정적 상생 및 조화 문구로 통일.
2. **부족 오행을 0개인 것만 인정하는 방안**:
   - 기각: 사주에 따라 모든 오행이 1개 이상인 경우 부족 오행을 찾지 못하는 문제가 발생하므로, '상대적 최솟값'을 부족 오행으로 산출하도록 표준화.
3. **지목 대상을 랜덤으로 섞는 방안**:
   - 기각: 동일한 룸 상태에서 새로고침하거나 호스트/게스트 화면 간 동기화 불일치(A2 요건 위반)를 방지하기 위해 `joinedOrder` 기반 결정론적 알고리즘 채택.

---

## 4. Consequences (결과 및 영향)

- **장점**:
  - 클라이언트 순수 함수로 구현되어 서버 부하 0, 네트워크 데이터 전송량 최소화.
  - 100% 결정론적이며 2~15인 모든 룸 크기에서 일관된 사용자 경험 보장.
  - 해커톤 현장에서 즉시 시연 가능한 시뮬레이터 UI(`PartyChemistryPlayground`) 확보.
- **주의 사항**:
  - 다른 팀원의 사주 엔진 출력 포맷(`{ 木: n, 火: n, 土: n, 金: n, 水: n }`)과 인터페이스 규약 일치 유지 필요.
